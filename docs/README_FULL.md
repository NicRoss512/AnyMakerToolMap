# Anymaker — разбор форматов (unlocks + карта/тайлы)

## 1. unlocks.txt

```
JSON  →  XOR с ASCII-байтами SteamID64 (ключ повторяется, 17 байт)  →  base32 (a-z2-7, LSB-first)
```

- Не стандартный base32 — биты пакуются от младшего бита (`value |= idx << bits`),
  поэтому `base64.b32decode` даёт мусор.
- Ключ = строка SteamID64 (17 цифр). Поэтому файл от другого аккаунта не подхватывается.
- Перенос: расшифровать старым ID → зашифровать новым.

`unlocks_tool.py` — decode / encode / rekey / merge / findkey.

Свой SteamID64 (17 цифр) передавай в `unlocks_tool.py` как ключ; чужие тут не нужны.

## 2. Тайлы → мировые координаты  (проверено на 37 341 объекте, 99.98 %)

Мир разбит на **ромбы со стороной 512** (гексагональная «ромбическая» решётка,
углы 60°/120°). Файлы: `tile_<tx>_<ty>_<layer>_<kind>.json`, `kind ∈ {static, level_3}`.

```
TZ = 512·√3/2 = 443.4050067      шаг ряда по Z
X  = 512·tx + 256·ty + 512·a + 256·b
Z  = TZ·(ty + b)                 a,b ∈ [0,1)
```

Ромб тайла (tx,ty) — четыре угла (X, Z):

```
A = ( 512·tx + 256·ty       ,  TZ·ty     )
B = ( 512·tx + 256·ty + 512 ,  TZ·ty     )
D = ( 512·tx + 256·ty + 768 ,  TZ·(ty+1) )
C = ( 512·tx + 256·ty + 256 ,  TZ·(ty+1) )
центр = A + (384, 221.7025)      площадь = 512·443.405 = 227 023 кв. ед.
```

Обратно:

```
ty = floor(Z / TZ)                       b = Z/TZ − ty
tx = floor((X − 256·Z/TZ) / 512)         a = (X − 256·Z/TZ)/512 − tx
```

`tilemap.py` — `tile`, `world`, `list`, `mapcfg`.

## 3. Что внутри сейва (на примере одного сохранения)

- `meta.json` → `application_version: v0.1.25`
- `scene.json` → `world_seed`, `gamemode`, `loot_level`,
  `dungeon_completed_count: 3`
- `tiles/` → файлы вида `tile_<tx>_<ty>_<layer>_<kind>.json`; грузятся только
  тайлы, в которых вы бывали (в примере — 355 файлов на 141 тайл)
- `dungeons/` → `dungeon_<N>_layer_<M>.json`, N 0…2, M 0…3
- Объекты: 37 341 шт. — пропсы 30 288 (заборы, отбойники, знаки, столбики —
  придорожные), лут на земле 3 918, NPC 2 670, здания 416 (+ игровые постройки)
- Ориентиры из `scene.json`: позиции игроков (`peers.peers[]`) и куполов
  (`creative_domes.domes[]`) — карта показывает их отдельным слоем «Игроки».
  Свои координаты смотри в самом инструменте, они у каждого свои.

## 4. Карта `worldmap.png` (4096×4096) — привязка найдена

Исходно: карта высот, 4 уровня на цветовое семейство, океан `(51,89,148)` 53.5 %.
Дороги на карте — цвет `(196,25,89)`.

### Калибровка (итоговая)

```
units_per_pixel  S  = 512/161 = 3.180124224     ровно 161 пиксель на тайл по X
origin (мир X при px=0)       OX = 74484.08
origin (мир Z при py=0, верх) OZ = 58513.82
flip_Z = true   (Z растёт вверх по картинке)

px = (X − OX) / S           X = OX + px·S
py = (OZ − Z) / S           Z = OZ − py·S
```

Проверка: 5 794 придорожных пропсов (знаки, отбойники, столбики, фонари) —
**медианное расстояние до дороги на карте = 0 пикселей**, 90 % ближе 16 px (50 ед.),
51 % стоят ровно на пикселе дороги (случайно было бы 2.95 % → обогащение ×17).
В океан попадает 6.6 % объектов (в основном по краю берега и крупные здания).

Погрешность: оптимум плоский в диапазоне S ∈ [3.178, 3.184] (±0.1 %), т.е. ±2 px
на краю карты.

### Что такое «квадраты»

Сетка 16×16, ячейка 256 px. **Буквы A…P идут по вертикали** (снизу вверх),
**цифры 00…15 — по горизонтали** (слева направо). Левый нижний = **A 00**,
правый верхний = **P 15**.

```
ячейка = 256 px = 814 × 814 ед. мира ≈ 1.59 × 1.84 тайла
```

Порядок переключается: в `save_map.html` кнопка **«Порядок»** в разделе «Вид»,
в `mapref.py` — флаг `--across` (тогда буквы идут по горизонтали, цифры по
вертикали). Углы при этом те же: левый низ A 00, правый верх P 15.

### Масштаб (оценка)

| что | значение |
|---|---|
| 1 ед. мира | ≈ 1 м (дорога 6.4 ед., столбы забора через 2.5 ед., фонари через 22.6 ед.) |
| тайл | 512 × 443 м |
| вся карта | 13 026 × 13 026 ед. = 13.0 × 13.0 км = 25.4 × 29.4 тайла |
| тайлы на карте | tx 79…119, ty 102…131 (810 штук) |
| сейв на карте | 141 тайл из 141, занимает 53 % × 62 % картинки |
| купол (из `creative_domes`) | попадает в верхнюю часть карты |
| позиция игрока (`peers.peers[]`) | показывается слоем «Игроки» |

### Команды

```bash
python3 mapref.py world 85000 52000   # что в точке мира: пиксель, квадрат, тайл
python3 mapref.py pixel 2000 1500     # что в пикселе карты
python3 mapref.py grid  L 12          # границы квадрата + какие тайлы в нём
python3 mapref.py tile  104 117       # где тайл на карте
python3 mapref.py table               # таблица всех 256 квадратов
```

## 6. Поиск запчастей по сейву — `save_map.html`

Один файл, открывается двойным кликом, интернета не нужно (JSZip внутри).
Интерфейс **по-английски по умолчанию**, переключатель языка — в шапке панели
(выбор запоминается в браузере).
Что делать: положить `save_map.html` и `worldmap.png` **в одну папку** — карта
подхватится сама при открытии. Дальше перетащить **ZIP сейва** в правую зону
(или выбрать через кнопку). Картинка нужна только чтобы рисовать точки: поиск,
координаты, тайлы, квадраты и CSV работают и без неё (если `worldmap.png` рядом
не окажется, приложение просто попросит перетащить его вручную).

Разбор полного сейва: 372 JSON-файла → **157 734 объекта**, **600 разных
названий**, ~10 с в браузере.

### Что и откуда читается

Имя предмета берётся из `definitions.components` **каждого файла** (нумерация
своя в файле!), а не из глобального списка.

| откуда | тег в поиске | что это |
|---|---|---|
| `floor_items.items[].item.component_def` | предметы на земле | **`component_def` важнее `_type`**: если предмет — коробка-заготовка (`vehicle_editor_add_component`), настоящая деталь лежит в `component_def` (12 600 штук, в т.ч. все `engine`) |
| `floor_items.items[].item._type` | предметы на земле | лут, валяющийся на земле |
| `vehicles.vehicles[].grids[].components[].def` | запчасти в технике | **установленные** детали: колёса, батареи, сиденья, двери… |
| `vehicles.vehicles[].grids[].components[].items[].item._type` | внутри контейнеров | то, что лежит в багажниках/ящиках самой техники |
| `props.props[].definition_id` | пропсы мира | заборы, бочки, знаки, стройматериалы |
| `actors.actors[]` | NPC | плюс их инвентарь: `inventory.slot_*` (и `children[].item`) |
| `entities.entities[].type` | объекты | имя лежит в `type` (напр. `train_junction`), а не в `definition_id` |
| `vehicles.vehicles[]` | техника/здания | целиком, отдельным названием `<техника/здание>` |

Важно:

- у **запчастей нет своих мировых координат** — в CSV и на карте они стоят в
  точке самой машины/здания, к которому прикручены;
- содержимое **данжей** (`dungeons/dungeon_<N>_layer_<M>.json`) тоже
  разбирается: у него мировые координаты = координаты входа, поэтому в CSV
  появляется колонка `zone` = `данж 1..3`;
- `Y` у предметов внутри данжей отрицательный (−13 и т.п.) — это нормально;
- объектов без позиции (`t = [0,y,0]`) в индексе нет;
- инвентарь NPC и вложенные `children` ставятся в точку самого NPC/предмета;
- в `scene.json` есть ещё `pseudo_objects.objects[]` (54 патруля/лагеря с `type`
  и `world_pos`) — сканер их считает, карта пока нет.

### Позиции игроков

Берутся из `scene.json` → `peers.peers[]` → `world_pos: [X, Y, Z]`. В одиночной
игре там одна запись (это ты), в сетевой — по записи на каждого, кто был в мире.
Слой **«Players»** в разделе «Вид» включён по умолчанию: на карте жёлтый кружок
с подписью `P1`, `P2`…, в панели — список с координатами, тайлом и квадратом
(клик по строке — перелёт, SteamID виден в подсказке).

### Категории (из данных игры, а не придуманы вручную)

В разделе «Поиск» — ряд чипсов с группами и количеством штук в сейве. Клик по
чипсу переключает три состояния: **только эта группа → кроме этой группы →
как было**. Можно включить несколько: например «кроме стройматериалов» и
«только еда» одновременно.

Первым в ряду стоит отдельный чипс **«В данжах»** — с той же трёх-state логикой.
Он нужен потому, что данж — это не категория предмета, а свойство конкретной
точки: в здешнем сейве 39 343 объекта из 157 874 (25 %) лежат внутри трёх
данжей и при поиске просто мешают. «Кроме данжей» убирает их все одним кликом,
«только данжи» — наоборот, показывает лишь подземки. Фильтры по категориям и по
данжам независимы и складываются.

Набор нажатых чипсов **запоминается в браузере** (localStorage), так что
«кроме стройматериалов и данжей» выставляется один раз и живёт дальше.

Группы берутся из файлов самой игры:

| откуда | что берём |
|---|---|
| `inventory_definitions.json` (372 предмета) | сначала `class` (он точнее: у колёс `class=wheel`, а `category=accessory`), потом `category` |
| `vehicle_component_definitions.json` (598 деталей) | `is_building_furniture` → мебель, `is_building_component` → стройматериалы, иначе `category` |
| `prop_definitions.json` (136 пропов) | категорий в игре нет — группа по ключевым словам (`fence`→стройматериалы, `lamp`→дороги, `pallet`→грузы, `tree`→природа) |
| `creature_` / `zombie_definitions.json` | живое |

Покрытие на тестовом сейве (876 файлов, 511 тыс. объектов): **1049 из 1049 названий (100 %)**.
Группы: стройматериалы, мебель, двигатель, колёса, механика, газ и жидкость,
электрика, управление, оружие, патроны, одежда, еда и питьё, медицина,
хранение, разное, дороги и знаки, грузы и тара, природа, объекты мира, живое,
техника и здания, не распознано.

Для справки, на большом сейве (876 файлов, 511 тыс. объектов): стройматериалы
315 396 шт. (62 % всего), мебель 80 109, разное 17 840, дороги 15 910,
электрика 15 429, грузы 13 428 — то есть «кроме стройматериалов» оставляет
~196 тыс. осмысленных объектов вместо полумиллиона.

Каждая находка показывает человеческое имя из игры (`food_cola` → «Cola»,
`battery_cell` → «Battery Cell»), поиск идёт и по нему; обе колонки
(`category`, `display_name`) уезжают в CSV.

### Примеры

| запрос | результат |
|---|---|
| `wheel` | 18 названий, 388 шт. (`wheel_car` 47, `wheel_rim_20` 45, `wheel_5_prong_tread` 41 …) |
| `battery` | 3 названия, 475 шт. (`battery_cell` 350, `battery_b` 64, `battery_a` 61) |
| `wheel_rim` | 6 названий, 133 шт. |
| `keycard` | 8 шт. |
| `engine` | **0** — такого слова в этом сейве нет, в игре оно называется иначе |

Слово `engine` не ищется не из-за поломки, а потому что в 600 названиях сейва
его нет: ищи по частям (`wheel`, `battery`, `seat`, `door`, `tank`, `glass`,
`light`, `panel`, `pipe`, `barrel`) или нажми «Топ-20», чтобы увидеть, что
вообще встречается. Поле «кроме» исключает лишнее: `barrel` + кроме `_a`
оставит только `barrel_b`.

### Управление

- колесо — зум, тяни мышью — панорама;
- кнопка **«☰ скрыть»** в правом верхнем углу убирает боковую панель — карта
  разворачивается на всё окно (повторно — вернуть);
- слой **«Квадраты A-P»** по умолчанию выключен, чтобы не загораживать карту;
- **«Выбрать всё»** отмечает все названия, прошедшие фильтр (их может быть
  больше 300 — над списком видно «показано 300 из 916»);
- **«Players»** — точки игроков из `scene.json` (в сетевой игре их несколько);
- точки: **бирюзовые** = все объекты сейва, **зелёные** = найденное;
- при приближении рисуются **все** объекты кадра (склейка повторов включается
  только когда в кадре больше ~80 тыс. точек и всё равно слиплось бы в кашу);
- поиск по подстроке, через запятую = несколько вариантов (`wheel,tyre`);
- «Где искать» — фильтр по типу источника, в т.ч. **только внутри данжей**;
- отметки в списке названий → точки на карте + список с координатами;
- клик по строке — перелёт к предмету, подсказка при наведении;
- «Выгрузить CSV» → `name;worldX;worldZ;worldY;tile;square;source;zone`.

## 7. Шпаргалка по геометрии сетки

```
ряд тайлов по Z:  443.405 ед.  (512·√3/2)
сдвиг X на ряд:   256 ед.
ромб тайла:       ширина 512, высота 443.405, диагонали 512
центр тайла:      A + (384, 221.7)
```
